# Sculpted monsters — downloading, adding and editing 3D models

The monsters in VIDHI are generated in code ([`src/models3d.js`](../src/models3d.js)).
That has a ceiling: procedural noise gives you texture, not anatomy. The detail
that makes a creature genuinely frightening — pores, sagging skin, asymmetric
growths, real muscle flow — comes from a sculpt.

So the renderer takes a sculpt if you give it one. This document is the whole
process: where to get models, how to check one before you commit to it, how to
drop it in, and how to fix it when it loads wrong.

## 1. Prove it works first (2 minutes)

Before spending an hour sourcing a model, confirm the plumbing works on your
machine. A sample model ships with the repo:
`assets/monsters/sample-monster.glb`. It is a deliberately crude rigged blob
with Idle / Walk / Attack / Death clips — it is ugly on purpose, its job is to
prove the pipeline.

Open [`src/monsterAssets.js`](../src/monsterAssets.js) and uncomment the
sample block:

```js
export const MONSTER_MODELS = {
  asura: {
    url: 'assets/monsters/sample-monster.glb',
    clips: { idle: 'Idle', walk: 'Walk', attack: 'Attack', death: 'Death' },
  },
};
```

Serve and play:

```sh
python3 -m http.server
# open http://localhost:8000
```

Every asura is now a lumpy cylinder that walks, swings and falls over. The
nagas and rakshasas are untouched, because you only configured `asura`. Comment
it back out to return to normal.

If that works, everything below is just swapping in a better file.

> The sample was generated by `tools/make-sample-monster.html` (open it in a
> browser and it re-exports the `.glb`). You will not normally need it.

## 2. Where to get free monsters

Ranked by how little work they need before they drop in.

### Quaternius — best starting point
**<https://quaternius.com>** · CC0 (public domain, no attribution required)

Free packs of rigged, animated creatures, distributed as `.gltf`/`.glb`
directly. The style is clean low-poly rather than photoreal horror, but they
are rigged with walk/attack/death clips already, so they work with zero
editing. If you want to see a real animated monster in the game in ten
minutes, start here.

### Sketchfab — the biggest selection
**<https://sketchfab.com>** · mixed licences, filter carefully

Search for `demon`, `rakshasa`, `naga`, `asura`, `creature`. Then **you must
set two filters**:
- **Downloadable** — most models on the site are view-only
- **License → CC0** (or CC-BY if you are willing to credit)

Download in **glTF** format when offered; it saves a conversion step. Quality
ranges from student work to genuinely excellent. This is where you will find
something actually scary. Free account required to download.

### Poly Pizza
**<https://poly.pizza>** · CC0 and CC-BY

An archive of the old Google Poly library plus new contributions, with a clean
glTF download button. Stylised, low-poly, lots of creatures.

### Kenney
**<https://kenney.nl/assets>** · CC0

Enormous, reliable, genuinely public domain. Mostly props and stylised
characters rather than horror monsters, but worth knowing about.

### OpenGameArt
**<https://opengameart.org>** · mixed (CC0, CC-BY, GPL)

Older and more chaotic, often in `.blend` or `.obj` rather than glTF, so
expect a Blender round-trip. Check each item's licence individually.

### itch.io asset packs
**<https://itch.io/game-assets/free/tag-3d>** · varies per pack

Indie asset packs, many free, some excellent. Licence terms are per-pack and
sometimes restrict commercial use.

### AI generation — if nothing fits
Meshy, Tripo3D and Rodin turn a text prompt or reference image into a rigged
`.glb` in minutes. Free tiers exist. For something as specific as "gaunt
ember-cracked asura demon, Tamil temple horror" this is often faster than
hunting a marketplace. Check the output's topology before committing —
AI-generated meshes can be dense and awkwardly rigged.

> I could not open any of these sites from the sandbox this repo was built in
> (outbound network is restricted), so treat the URLs as the well-known
> addresses they were, and the licence filters as the thing to verify yourself
> at download time rather than as a guarantee.

## 3. Licensing — read before you publish

This repo deploys publicly to GitHub Pages. A model you add ships to everyone
who loads the page, so the licence matters.

| Licence | Can you use it here? | Obligation |
|---|---|---|
| **CC0 / Public domain** | Yes | None. Simplest choice. |
| **CC-BY** | Yes | You must credit the author, visibly. Add them to the README. |
| **CC-BY-SA** | Careful | Share-alike may oblige you to license derivatives similarly. |
| **CC-BY-NC** | Not for anything commercial | Non-commercial only. |
| **"Free for personal use"** | Usually not | A public deployment often is not "personal use". |
| **Editorial / no-redistribution** | No | Cannot be redistributed in a repo. |

If you use anything that is not CC0, add an attribution section to the README
naming the model, the author, the source URL and the licence. Do that at the
same time you add the file, not later.

## 4. Download and inspect

Save models under `assets/monsters/`:

```sh
mkdir -p assets/monsters
# then move your download in, e.g.
mv ~/Downloads/scary-demon.glb assets/monsters/asura.glb
```

**Prefer `.glb` over `.gltf`.** A `.glb` is one self-contained binary with the
textures embedded. A `.gltf` is JSON plus a folder of side-car `.bin` and image
files, all of which must keep their relative paths — easy to break.

Now inspect it. This repo ships a tool that reads the file directly and tells
you everything you need for the config:

```sh
node tools/inspect-glb.mjs assets/monsters/asura.glb
```

It reports:

- **triangle count** — flags anything heavy
- **bounding box** — so you can see whether it is Y-up and where its feet sit
- **skins** — whether it has a skeleton at all
- **animation clip names**, with a ready-to-paste `clips: { … }` block
- **blocking extensions** — Draco/KTX2/meshopt, which this game's loader cannot read

Example output:

```
  triangles          800
  skins              1
  animations (4)
    "Idle"   -> auto-matches idle
    "Walk"   -> auto-matches walk
  suggested config:
    clips: {
      idle: 'Idle',
      walk: 'Walk',
    },
  no blocking extensions - this should load.
```

If it says **WILL FAIL TO LOAD**, jump to
[Troubleshooting → Compressed models](#compressed-models-draco-ktx2-meshopt).

## 5. Add it to the game

Edit [`src/monsterAssets.js`](../src/monsterAssets.js):

```js
export const MONSTER_MODELS = {
  asura: {
    url: 'assets/monsters/asura.glb',
    clips: { idle: 'Idle', walk: 'Walk', attack: 'Attack', death: 'Death' },
  },
};
```

That is the entire integration. Every field except `url` is optional:

| Field | Default | What it is for |
|---|---|---|
| `url` | *required* | Path from the page root, e.g. `assets/monsters/asura.glb` |
| `clips` | auto-match | Clip names in the file. Omit and the loader guesses from names containing `idle`, `walk`/`run`, `attack`/`strike`, `death`/`die`. |
| `yaw` | `0` | Radians, if the sculpt faces something other than `+Z`. `Math.PI` turns it around. |
| `scale` | `1` | Extra multiplier **on top of** the automatic height fit. You rarely need this. |
| `offsetY` | `0` | Tiles, if the model hovers or sinks. Rarely needed — the loader stands it on the floor from its bounding box. |

Valid keys are `asura`, `naga`, `rakshasa` and `boss` (Mahishasura). Anything
you leave out stays procedural, so you can replace one species at a time. If
`boss` is unset, Mahishasura uses the `rakshasa` sculpt when there is one.

**You do not need to touch scale.** The loader measures the model's bounding
box and fits it to that species' gameplay height (asura 1.02 tiles, naga 1.06,
rakshasa 1.18, Mahishasura 1.34), then stands its feet on the floor. A model
authored in centimetres and one authored in metres both come out right.

Reload the page. Open the browser console — any problem is reported there
prefixed with `[vidhi]`, and the game falls back to the procedural monster
rather than breaking.

## 6. Editing models — Blender

**[Blender](https://www.blender.org)** is the open-source tool for this. Free,
GPL, runs on Windows/macOS/Linux, and reads and writes glTF natively — no
plugin needed.

### The basic round trip

1. **File → Import → glTF 2.0**, pick your `.glb`
2. Edit (see below)
3. **File → Export → glTF 2.0**, and in the export sidebar set:
   - **Format: glTF Binary (.glb)** — self-contained, one file
   - **Include → Selected Objects** if you only want part of the scene
   - **Transform → +Y Up** ✅ (this is the default and must stay on)
   - **Data → Mesh → Apply Modifiers** ✅
   - **Data → Material → Materials: Export** ✅
   - **Animation → Animation** ✅ if the model has clips
   - **Compression** ❌ **off** — Draco will not load (see troubleshooting)
4. Save over `assets/monsters/…glb` and reload the page

### Things you will actually want to do

**Make it face the right way.** The game expects the monster to face `+Z`.
Select the object, `R` `Z` `180` `Enter` to spin it, then
**Object → Apply → Rotation** so the change is baked in. (Or skip Blender and
set `yaw: Math.PI` in the config.)

**Stand it on the floor.** Move it so the feet sit at `Z = 0` in Blender's
world (Blender is Z-up; the exporter converts). Then
**Object → Apply → All Transforms**. The loader compensates anyway, but a
clean origin makes everything else predictable.

**Reduce triangle count.** If `inspect-glb.mjs` reported a heavy model: select
the mesh, **Modifier Properties (wrench) → Add Modifier → Generate → Decimate**,
set Ratio to `0.5` (half the triangles), check it still looks right, then
**Apply**. Aim for under ~20k triangles per monster — up to nine asuras can be
on screen at once.

**Make it grimmer.** In the Shading workspace, drop the base colour's
saturation and brightness, raise Roughness to ~0.7, and add a Bump node fed by
a Noise Texture. This matches how the procedural monsters are shaded and keeps
a downloaded model from looking like a bright toy in a dark temple.

**Cut off pieces you dislike.** `Tab` into Edit Mode, hover the part, press `L`
to select the connected island, `X → Vertices` to delete it. Good for removing
weapons, wings, or a silly hat.

**Scale it.** Don't. The loader fits it automatically.

### Quick viewers, no install

- **<https://gltf-viewer.donmccurdy.com>** — drag a `.glb` in, see it render and
  play its animations. Fastest way to check a download before wiring it up.
- **<https://threejs.org/editor>** — the three.js editor; imports glTF and shows
  the scene graph, which is useful when a model loads but nothing appears.

## 7. Editing without Blender — gltf-transform

**[gltf-transform](https://gltf-transform.dev)** is an open-source (MIT) CLI
that edits glTF files directly. No install needed — `npx` fetches it:

```sh
# Report what is inside (similar to inspect-glb.mjs, more detail)
npx @gltf-transform/cli inspect assets/monsters/asura.glb

# Strip Draco/meshopt compression so this game's loader can read it
npx @gltf-transform/cli dedup in.glb out.glb

# Shrink oversized textures (a 4K skin is wasted on a monster in the dark)
npx @gltf-transform/cli resize in.glb out.glb --width 1024 --height 1024

# Reduce triangles
npx @gltf-transform/cli simplify in.glb out.glb --ratio 0.5 --error 0.01

# Merge a .gltf + folder of side-car files into one self-contained .glb
npx @gltf-transform/cli copy in.gltf out.glb
```

This is the fastest route for fixing a technically-broken model. For anything
artistic, use Blender.

## 8. Getting animations — Mixamo

A model with no skeleton loads fine but stands there: the procedural poser
cannot drive a foreign rig.

**[Mixamo](https://www.mixamo.com)** (Adobe, free with an account) auto-rigs a
humanoid mesh and gives you a large library of animations:

1. Upload your mesh (`.fbx` or `.obj`)
2. Place the rig markers (chin, wrists, elbows, knees, groin) and let it rig
3. Pick animations — search `idle`, `walk`, `zombie attack`, `falling back death`
4. Download each as **FBX Binary**, "With Skin" for the first and "Without
   Skin" for the rest
5. In Blender: import the skinned FBX, then import the others and copy their
   actions onto the same armature
6. Rename the actions to `Idle`, `Walk`, `Attack`, `Death`
7. Export as `.glb` with **Animation → Export → Actions** enabled

Mixamo only works on roughly humanoid meshes — it will not rig the naga's
coiled tail. For non-humanoids, either animate in Blender or accept a static
model.

**Non-humanoid shortcut:** a model with no clips at all still gets a death
animation — the loader topples and sinks it in code when the file has no
`death` clip.

## 9. Troubleshooting

Everything the loader complains about is logged to the browser console with a
`[vidhi]` prefix, and always falls back to the procedural monster rather than
breaking the game.

### Nothing changes; monster is still procedural

Open the console.

- `[vidhi] could not load … sculpt` → wrong path. `url` is relative to the page
  root, not to `src/`. It should look like `assets/monsters/asura.glb`.
- No message at all → check the key is spelled exactly `asura`, `naga`,
  `rakshasa` or `boss`, and that you actually saved the file.
- Loading from `file://` → module imports and `fetch` are blocked. Serve over
  HTTP (`python3 -m http.server`).

### Compressed models (Draco, KTX2, meshopt)

`inspect-glb.mjs` flags these, and the console shows
`No DRACOLoader instance provided`. The decoders are not vendored here.

Fix by re-exporting without compression (Blender: **Compression** off), or:

```sh
npx @gltf-transform/cli dedup compressed.glb plain.glb
```

### It loads lying down, or facing away

- Lying down → not Y-up. Re-export from Blender with **+Y Up** checked.
  `inspect-glb.mjs` warns when the longest axis is not Y.
- Facing away → set `yaw: Math.PI` in the config, or rotate and
  **Apply → Rotation** in Blender.

### It is black, or a flat grey blob

Textures did not come along. Almost always a `.gltf` whose side-car files were
not copied. Convert to a self-contained `.glb`:

```sh
npx @gltf-transform/cli copy model.gltf model.glb
```

If it is genuinely untextured, assign a material in Blender before exporting.

### It floats or sinks into the floor

The loader stands it on its bounding box, so this usually means stray geometry
(a ground plane, a hidden helper) is inflating the box. Delete it in Blender.
`offsetY` (in tiles) is the escape hatch.

### Animations do not play

Run `inspect-glb.mjs` and check the reported clip names against your `clips`
block — they are matched exactly first, then loosely by keyword. A clip named
`Armature|mixamo.com|Layer0` matches nothing; rename it in Blender, or name it
explicitly in the config.

### The game gets slow

A downloaded model can easily be 100k+ triangles, and level 3 puts fifteen
enemies on screen. Decimate in Blender or `simplify` with gltf-transform, and
shrink textures above 1024px. The renderer already drops shadows automatically
if it cannot hold 30fps, so check whether shadows disappeared — that is the
symptom of a too-heavy scene.

### It looks bright and cartoonish next to everything else

The procedural monsters are deliberately dark, desaturated and matte. A
downloaded model with a bright albedo will not sit in the same world. In
Blender, drop the base colour's saturation and value and raise Roughness.

## 10. What the loader actually does

For reference, [`src/monsters.js`](../src/monsters.js) does this per model:

1. Loads the `.glb` once per species, in the background, at startup. Enemies
   already on screen are rebuilt when it arrives — and only the species that
   actually got a sculpt, so nothing else visibly resets.
2. Measures the bounding box and scales it to that species' gameplay height,
   then offsets it so its feet are on the floor.
3. Clones the skeleton per instance (via `SkeletonUtils`), so nine asuras
   animate independently rather than in lockstep.
4. Clones materials per instance, so one monster can flash red when hit or fade
   out as a corpse without dragging its species with it.
5. Turns on shadow casting and disables frustum culling (skinned bounding
   boxes go stale as the pose changes).
6. Builds an `AnimationMixer` and maps `idle`/`walk`/`attack`/`death` onto the
   same state the procedural poser reads — how fast the monster is travelling,
   whether it is winding up, whether it is dying — with a 0.18s crossfade.
7. Falls back to the procedural rig if any of that fails.

The gameplay simulation never knows the difference: hit boxes, speeds, damage
and AI all come from [`src/maps.js`](../src/maps.js) and
[`src/game.js`](../src/game.js), not from the model.

### Files involved

```
src/monsterAssets.js          you edit this - names your .glb files
src/monsters.js               factory: sculpt if present, procedural otherwise
src/models3d.js               the procedural monsters
lib/jsm/loaders/GLTFLoader.js vendored three.js loader
lib/jsm/utils/                SkeletonUtils + BufferGeometryUtils (its deps)
tools/inspect-glb.mjs         tells you what is in a .glb
tools/make-sample-monster.html  regenerates the sample .glb
assets/monsters/              put your models here
```

> `lib/jsm/` keeps three.js's original directory layout on purpose:
> `GLTFLoader.js` imports its siblings as `../utils/…`, so flattening the files
> into `lib/` breaks it at runtime. Keep the tree shape when updating three.
